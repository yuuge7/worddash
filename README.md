# WordDash

A Wordle-style word-guessing game for Android, built with Flutter. Unlike
the original, there's no daily limit - play as many rounds as you want,
across multiple word categories, in **English** or **Romanian**.

## Features

- **Unlimited play** - guess a word, then jump straight into the next one.
  No daily lockout.
- **Categories** - word packs beyond the classic "any word" list (General,
  Animals, more to come). Each category is just a plain word list, so
  adding a new niche is a five-minute job (see below).
- **English & Romanian** - switch languages from the home screen. Word
  lists and UI text are both translated.
- **Local stats** - games played, won, and current streak, saved on-device.
- **Automated releases** - every push to `main` builds a signed APK and
  publishes it as a new GitHub Release (see [Releases](#releases)).

## Tech stack

- [Flutter](https://flutter.dev) / Dart, Android target only
- [`provider`](https://pub.dev/packages/provider) for state management
- [`shared_preferences`](https://pub.dev/packages/shared_preferences) for
  local stats persistence
- GitHub Actions for CI/CD

## Getting started

### Prerequisites

- [Flutter SDK](https://docs.flutter.dev/get-started/install) (stable
  channel)
- Android SDK (installed automatically if you use Android Studio, or via
  `sdkmanager` if you prefer the command line)
- A physical Android device or emulator

### Setup

This repo ships the app's Dart source (`lib/`) and the few `android/`
files that actually matter (signing, the manifest, the app icon source)
- but not the rest of the generated Android platform folder. That
boilerplate is version-pinned to whatever Flutter/Gradle/Kotlin versions
you have installed, so it's more reliable to generate it fresh on your
own machine than to have it hand-written and possibly stale here.

```bash
git clone https://github.com/yuuge7/worddash.git
cd worddash

# Generates the rest of android/ using your local Flutter SDK's current
# templates. --org must match the package used everywhere else in this
# project. This will NOT overwrite the android/ files already in the
# repo (build.gradle.kts, AndroidManifest.xml) - those stay as shipped.
flutter create --platforms=android --org com.yuuge7 .

flutter pub get

# Generates the Android launcher icons from assets/icon/ - see "App
# icon and name" below.
dart run flutter_launcher_icons

flutter run
```

That's it for a debug build. Signing is already wired up (see
[Signing](#signing)) - `flutter build apk --release` works out of the box
against the keystore already in this repo's root.

### Running tests

```bash
flutter test
```

## Adding words or a category

Everything lives under `lib/data/`:

1. Add your words to an existing list (`words_en_general.dart`,
   `words_ro_animals.dart`, etc.), or create a new file following the same
   pattern - one `const List<String>`, all entries **uppercase** and the
   **same length**.
2. For a brand-new category, register it in `lib/data/categories.dart` by
   adding a `WordCategory` with a display name per language and its word
   lists.
3. That's the whole change - the home screen and game screen both read
   from that registry automatically.

## App icon and name

The launcher label is set in `android/app/src/main/AndroidManifest.xml`
(`android:label="WordDash"`). The icon is generated by
[`flutter_launcher_icons`](https://pub.dev/packages/flutter_launcher_icons)
from two source files under `assets/icon/`:

- `icon.png` - the full square icon (used for the legacy launcher icon).
- `icon_foreground.png` - just the glyph on a transparent background,
  used as the foreground layer of the Android adaptive icon. The
  background layer is just a solid color (`adaptive_icon_background` in
  `pubspec.yaml`), no image needed.

To change either: edit/replace those two PNGs (or point `image_path` /
`adaptive_icon_foreground` in `pubspec.yaml` at new ones), then re-run:

```bash
dart run flutter_launcher_icons
```

That regenerates every density under `android/app/src/main/res/mipmap-*/`
- you never edit those directly.

To rename the app itself: `worddash` is used as the Dart package name
(`pubspec.yaml`) and the Android `applicationId`/`namespace`
(`com.yuuge7.worddash` in `build.gradle.kts` and the folder path under
`android/app/src/main/kotlin/`). Renaming any of these after the fact is
a find-and-replace, but changing `applicationId` post-release means
Android treats it as a different app - decide before your first real
release, not after.

## Signing

Android requires every release build to be signed with the same key every
time - if the key ever changes, the Play Store (or your users, for
sideloaded APKs) will treat it as a different, incompatible app. Two files
matter:

| File | What it is | Committed to git? |
|---|---|---|
| `worddash-release-key.jks` | The actual signing key (repo root) | **No** - gitignored |
| `android/key.properties` | Passwords + alias pointing at that key | **No** - gitignored |

`android/key.properties.example` *is* committed as a template so
contributors know the expected shape without ever seeing a real
password. `android/app/build.gradle.kts` already reads `key.properties`
and wires it into the release build type - if it's missing (e.g. a
fresh contributor checkout with no release key), release builds fall
back to the debug key automatically, so `flutter build apk --release`
still works for everyone, it just won't produce a Play-Store-valid
build for anyone but you.

### Setting this up on a new machine

The keystore and `key.properties` both already exist in this repo as
shipped, signed with the real release key. If you're moving to a
**different** machine later and starting from a clean clone (where
both are correctly gitignored and therefore absent), restore them from
your backup - back them up somewhere safe now, a password manager or
encrypted drive, **not** a public repo:

1. Copy `worddash-release-key.jks` into the project root.
2. Copy your saved `key.properties` into `android/key.properties`.
3. `flutter build apk --release` now produces a signed APK at
   `build/app/outputs/flutter-apk/app-release.apk` - no other setup
   needed, `build.gradle.kts` already does the wiring.

If you've **lost** the keystore, there's no way to recover it or produce
an update that Android will accept as the same app - you'd have to publish
under a new signing key (and, on the Play Store, effectively a new app
listing). Back it up before you need it.

### Setting up the signing secrets in GitHub Actions

The CI workflow needs the same key to sign the APKs it releases. It never
reads a committed file - it reconstructs the keystore at build time from
repository secrets, then deletes it when the job finishes.

In your repo: **Settings → Secrets and variables → Actions → New repository
secret**, add:

| Secret name | Value |
|---|---|
| `KEYSTORE_BASE64` | `base64 -w0 worddash-release-key.jks` (the output) |
| `KEYSTORE_PASSWORD` | the `storePassword` from `key.properties` |
| `KEY_PASSWORD` | the `keyPassword` from `key.properties` |
| `KEY_ALIAS` | `worddash` |

## Releases

`.github/workflows/release.yml` runs on every push to `main`:

1. Builds a signed release APK.
2. Tags and publishes it as a GitHub Release named **WordDash vX.Y**,
   where `X` is the major version from `pubspec.yaml` and `Y` is that
   workflow's run number - which only ever increases, so a release is
   never overwritten; every push creates a new one.
3. Uploads the APK to that release.

To start a new major line (e.g. move from `v1.x` to `v2.0`), bump the
leading number in the `version:` line of `pubspec.yaml` and push - the
next release will pick it up automatically.
